# Direct-access duas and optional reminders

The app keeps its existing home photos, colors, four destinations, horizontal prayer/wudu/ghusl guides and lesson search/bookmarks. A new entry on Home and Tools opens seven dua cards. No reference-image redesign has been attempted because no image was received.

The dua library includes collapsible subcategories, search across real titles/Arabic/meaning translations (Arabic marks and Persian kaf/yeh variants normalized only in the search index), separate saved and recent lists, and a pager confined to the selected subcategory. Arabic display/copy bytes remain unchanged. Reader controls include persistent Arabic size, reading font, copy/share, source/grade and missing/review notices. No recording was supplied; the audio control is absent and no player is created for an empty/missing file. Sourced repetitions have counters. The same canonical entries are linked from the corresponding Hanafi guide stages; no Witr qunut is inserted into the ordinary-prayer guide. Existing lesson bodies remain intact.

Settings contain an independently default-off reminder switch, explicit consent explanation, Android 13+ permission request, 1–8 daily slots, local start/end times and category selection. One **inexact** AlarmManager alarm is scheduled at a time. API 21/22 use `set`, newer devices use `setAndAllowWhileIdle`; no exact-alarm permission is requested for this feature. Separate request codes, notification channel and receivers leave adhan and Ramadan scheduling unchanged. Boot, update and clock/time-zone broadcasts restore the next reminder. A failed/missing translation or unresolved Arabic/source/grade excludes a record from reminders and the UI reports an empty eligible pool.

Favorites have three tickets while drawing from the remaining deck; each Arabic payload still appears once per cycle. Weight therefore means earlier placement, not extra copies within a cycle. A normalized Arabic hash keeps identical-text aliases from repeating after an alias is bookmarked. The deck, recent list, dua bookmarks, preferences and last-delivered/scheduled slot are persisted separately from existing lesson data. Duplicate/stale broadcasts are rejected; the same notification tag is reused if a notification post is retried after a storage failure. This is not a claim of OS-level exactly-once delivery.

Android may delay or throttle reminders, especially in Doze, restricted battery modes or short windows. A late reminder remains inside the chosen civil-date window; expired windows are skipped, without a burst of catch-up notifications. Turning the feature off cancels its next alarm. Notification permission denial does not delete any bookmarks or consume the deck. Notifications contain sourced Arabic and a short selected-language meaning with an explicit translation-review notice.

Five new instrumentation tests cover actual asset parsing/search, pager/audio absence, exact owner text, consent and DataStore preservation; they were **compiled only**. No adb device or KVM is available. Notification delivery, reboot, real navigation, Arabic shaping, screen readers and small/large-font layouts must be checked on a phone.
